Owis Find Deal API

Search the online marketplaces of a country (Amazon, AliExpress, Temu, SHEIN, eBay, …) for a product and get the offers with price, currency and link. Use it from your own servers over HTTP, or let AI agents call it as tools over MCP.

The base URL in the examples is http://localhost:3002 (the local Docker stack). Use your server's address instead. The machine-readable description is at /api/v1/openapi.json.

Quick start

  1. Ask the service owner for an API key. They make it in the admin panel (API clients) and choose its scopes, countries and daily allowance. The key looks like ofd_live_… (49 characters) and is shown once: keep it in your server's secret store, never in an app or web page.
  2. List the countries: 
    curl http://localhost:3002/api/v1/countries
  3. Search: 
    curl -X POST http://localhost:3002/api/v1/search \
  -H "Authorization: Bearer $OFD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"usb c hub","country":"jor"}'

A new search takes 20–60 seconds. The same search again within 48 hours is answered at once from the cache, and is free.

Authentication

Every call except /api/v1/health, /api/v1/countries and these docs needs Authorization: Bearer <token>:

TokenForNotes
API key ofd_live_…Your servers and AI agentsOwn daily allowance and per-second limit; may be limited to some countries, IP addresses and scopes; can expire, be rotated (old key keeps working for a grace period) or revoked.
Firebase ID token (JWT)The mobile / web appThe user's plan decides the daily allowance. Not accepted by /mcp.

Scopes of an API key: search (search endpoints and the MCP tool search_products) and countries (the MCP tool list_countries).

Search

POST /api/v1/search — waits for the answer.

FieldType
titlestring, 2–200 charactersWhat to search for. Short is best: brand + model.
countrystringA code from /api/v1/countries, e.g. jor.
refreshboolean, optionaltrue skips the cache (a live search: slower, counts against the allowance).

Answer (shortened):

{
  "query": "usb c hub",
  "country": "jor",
  "results": [
    {"market": "amazon", "title": "Anker USB C Hub, 7-in-1", "link": "https://www.amazon.com/dp/…",
     "price": 29.99, "currency": "USD", "position": 1, "provider": "serpapi"}
  ],
  "markets": {"amazon": "ok", "aliexpress": "ok", "temu": "ok", "shein": "no_results"},
  "took_ms": 41250,
  "fetched_at": "2026-10-26T09:12:03Z",
  "cached": false,
  "stale": false
}

Headers: X-Cache (HIT, STALE, MISS), X-Plan (api for keys), X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset (Unix seconds), X-Request-ID.

markets gives each marketplace's status: ok, no_results or error (that source failed; the others still answer). A product whose link_type is search links to the marketplace's own search because no product page was found.

Asynchronous search

For live searches without holding a connection open for a minute:

curl -i -X POST http://localhost:3002/api/v1/searches \
  -H "Authorization: Bearer $OFD_KEY" -H "Content-Type: application/json" \
  -d '{"title":"usb c hub","country":"jor"}'

HTTP/1.1 202 Accepted
Location: /api/v1/searches/srch_…
Retry-After: 5

{"id":"srch_…","status":"running","request":{…},"created_at":"…","finished_at":null}

Then poll every ~5 seconds until status is done (with result, the same object as the synchronous answer) or failed (with error: the status and code the synchronous search would have given):

curl http://localhost:3002/api/v1/searches/srch_… -H "Authorization: Bearer $OFD_KEY"
  • A cached answer is already done in the 202.
  • Bad input, a used-up allowance, a missing scope or a country the key may not use are refused at once (no job).
  • Only the caller can read its jobs (others get 404). Finished jobs are kept 1 hour.
  • At most 10 jobs per caller run at once (429 too_many_jobs). Polling has its own limit (5 per second) and does not count as searches.

Webhooks

Instead of polling, an API key can add "webhook_url":"https://…" to POST /api/v1/searches. When the search finishes, the job is POSTed there. The client needs a webhook secret first: the service owner makes it in the admin panel (API clients → Webhook secret, shown once, whsec_…). Without one the request is refused with 400 webhook_not_configured.

Header
X-OFD-Signaturet=<unix seconds>,v1=<hex HMAC-SHA256(secret, "<t>." + raw body)>
X-OFD-Eventsearch.completed or search.failed
X-OFD-DeliveryThe job id; the same on every attempt, so you can drop repeats.
  • Answer with any 2xx within 10 seconds. Otherwise it is retried: 3 attempts in all (at once, after 5 s, after 30 s). Redirects are not followed.
  • Only https URLs on public addresses are accepted.
  • The job (GET /api/v1/searches/{id}) shows how the delivery went in webhook.status: pending, delivered or failed.

Always check the signature on the raw body, before parsing it, and refuse old timestamps:

# Python
import hashlib, hmac, time

def verify(secret: str, header: str, body: bytes, tolerance: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    t, sig = parts.get("t", ""), parts.get("v1", "")
    if not t.isdigit() or abs(time.time() - int(t)) > tolerance:
        return False
    want = hmac.new(secret.encode(), t.encode() + b"." + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, sig)
// Node.js
const crypto = require("node:crypto");

function verify(secret, header, rawBody, tolerance = 300) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=", 2)));
  const t = Number(parts.t);
  if (!Number.isInteger(t) || Math.abs(Date.now() / 1000 - t) > tolerance) return false;
  const want = crypto.createHmac("sha256", secret).update(`${parts.t}.`).update(rawBody).digest("hex");
  const got = Buffer.from(parts.v1 || "", "utf8");
  return got.length === want.length && crypto.timingSafeEqual(got, Buffer.from(want, "utf8"));
}

A new webhook secret replaces the old one at once.

AI agents (MCP)

AI agents can call the search as tools over the Model Context Protocol. The endpoint is POST /mcp (Streamable HTTP) and takes the same API keys (login tokens are not accepted).

ToolScopeArgumentsReturns
list_countriescountriesnoneThe countries this key may search in, with currency and marketplaces. Free.
search_productssearchtitle, country, optional refreshThe same result as POST /api/v1/search, plus quota (the allowance left). Metered the same way.

Results come as structured content (with an output schema) and as the same JSON in a text block. When a tool cannot run — allowance used up, country not allowed, scope missing, every marketplace failing — the result has isError: true and a text block {"error":{"code":"…","message":"…"}}, so the agent can read why and adjust.

Connect a client

Claude Code:

claude mcp add --transport http owis-find-deal http://localhost:3002/mcp \
  --header "Authorization: Bearer ofd_live_…"

Clients that are configured with JSON (Cursor, VS Code, and others that support remote servers with headers):

{
  "mcpServers": {
    "owis-find-deal": {
      "type": "http",
      "url": "http://localhost:3002/mcp",
      "headers": { "Authorization": "Bearer ofd_live_…" }
    }
  }
}

Clients that only start local (stdio) servers can go through the mcp-remote bridge:

npx -y mcp-remote http://localhost:3002/mcp --header "Authorization: Bearer ${OFD_KEY}"

In your own agent code, use any MCP SDK's Streamable HTTP client with the Authorization header.

The key gives access to your allowance. Put it in the client's secret or environment settings, not in a shared file or repository.

Protocol details

  • Versions: 2026-07-28 (stateless: each request carries params._meta["io.modelcontextprotocol/protocolVersion"] and the headers MCP-Protocol-Version, Mcp-Method, Mcp-Name; server/discover lists what the server supports) and 2025-03-26, 2025-06-18, 2025-11-25 (with the initialize handshake).
  • Every request is answered with one JSON object. No sessions (Mcp-Session-Id is never issued), no SSE streams; GET /mcp answers 405. One message per request (no batches).
  • An unsupported version answers 400 with JSON-RPC error -32022 and data.supported; headers that do not match the body answer 400 with -32020.
  • search_products waits for the search (20–60 s for a new one), so give your client a timeout of at least 90 seconds.

A raw call (2026-07-28):

curl http://localhost:3002/mcp \
  -H "Authorization: Bearer $OFD_KEY" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -H "MCP-Protocol-Version: 2026-07-28" -H "Mcp-Method: tools/call" -H "Mcp-Name: search_products" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{
        "name":"search_products","arguments":{"title":"usb c hub","country":"jor"},
        "_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28",
                 "io.modelcontextprotocol/clientCapabilities":{}}}}'

Limits and cost

LimitDefault for a new API keyWhen reached
Live searches per day100 (set per key)429 quota_exceeded with Retry-After until the reset. Cached answers stay free and keep working.
Requests per second1 per second, bursts of 5 (set per key)429 rate_limited with Retry-After.
Asynchronous jobs running10429 too_many_jobs.
Polling a job / MCP messages5 per second, bursts of 20429 rate_limited.
Request body64 KB400 invalid_request.

Prices change: fetched_at says when an answer was fetched. A cached answer older than its fresh period is marked stale and refreshed in the background; ask with "refresh": true only when you need prices from right now.

Errors

Errors have the body {"error":{"code":"…","message":"…"}}. Act on code; message is for people and may change.

StatusCodeMeaning
400invalid_requestBad JSON, an unknown field, a title not 2–200 characters, a bad webhook URL.
400unsupported_countryNot a code from /api/v1/countries.
400webhook_not_configuredThe API client has no webhook secret yet.
401unauthorizedMissing, invalid, expired or revoked token or key.
402payment_requiredAn app user's free searches are used up (never for API keys).
403forbiddenThe key lacks the scope, or may not be used from this address.
403country_not_allowedThe key may not search in this country.
404not_foundNo such job for this caller (or older than 1 hour).
429rate_limited, quota_exceeded, too_many_jobsSee Limits; wait Retry-After seconds.

503service_unavailableTemporarily unavailable or busy; retry.
—timeout, job_lostOnly in a failed job: the search took too long, or the server stopped during it. Start it again.

OpenAPI

The full description of the HTTP API, including the webhook, is an OpenAPI 3.1 document: /api/v1/openapi.json. Load it into Swagger UI, Redoc, Postman or Insomnia, or generate a client from it (for example with openapi-generator).
